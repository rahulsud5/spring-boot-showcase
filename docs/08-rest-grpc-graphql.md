# 08 · REST, gRPC and GraphQL

order-service exposes **REST** and **GraphQL**, calls catalog prices over **REST** (HTTP interface
client) and checks stock over **gRPC**. inventory-service serves gRPC.

## 1. When to use which

| | REST (JSON over HTTP) | gRPC (Protobuf over HTTP/2) | GraphQL |
|---|---|---|---|
| Best for | Public APIs, CRUD-ish resources, browser clients | Internal service-to-service calls, low latency, streaming | Client-driven reads over a graph of data (BFF, mobile) |
| Contract | OpenAPI (generated by springdoc) | `.proto` file (code generation), strongly typed | Schema (`schema.graphqls`), strongly typed |
| Payload | Text, human-readable | Binary, compact, fast to (de)serialize | JSON; the client selects fields |
| Caching | HTTP caching, CDNs, ETags | None built in | Hard (POST, varying shapes); persisted queries help |
| Streaming | SSE / WebSocket | Native: server, client, bidirectional | Subscriptions (WebSocket) |
| Browser support | Native | Needs gRPC-Web / a proxy | Native |
| Errors | HTTP status + Problem Details | Status codes (`NOT_FOUND`, `UNAVAILABLE`, ...) + rich details | HTTP 200 with an `errors` array |
| Evolution | Versioning (header/URL) | Add fields with new numbers; never reuse numbers | Add fields, `@deprecated` |

## 2. REST (order-service `OrderController`)

| Endpoint | Shows |
|---|---|
| `POST /api/orders` + `Idempotency-Key` | 201 + `Location`; a replay with the same key returns 200 with the same order; a concurrent duplicate while the first is still running returns 409 |
| `GET /api/orders/{id}` with `X-API-Version: 1` or `2` | **Spring 7 API versioning**: same path, different representation |
| `GET /api/orders/mine?cursor=` | Keyset pagination with an opaque cursor |
| `GET /api/orders?status=&from=&minTotal=` | Dynamic filters (Specifications), `PagedModel` for a stable JSON page shape |
| `POST /api/orders/{id}/cancel`, `/ship` | State transitions as sub-resources (actions), 409 on conflicting state |
| `GET /api/orders/reports/daily-revenue` | Reporting endpoint (`@PreAuthorize("hasRole('ADMIN')")` on the service method) |
| `POST /api/webhooks/payments` | Machine-to-machine with an API key (`ApiKeyAuthenticationFilter` → `ROLE_PARTNER`), 202 Accepted |

**API versioning (Spring Framework 7):**
```java
// WebConfig
configurer.useRequestHeader("X-API-Version").addSupportedVersions("1", "2").setDefaultVersion("1");

// OrderController
@GetMapping(path = "/{id}", version = "1") OrderDetails v1(...)
@GetMapping(path = "/{id}", version = "2") OrderDetailsV2 v2(...)
```
An unsupported version returns **400**. Other strategies: path segment (`usePathSegment(1)`),
query parameter, media type parameter. `version = "1.2+"` means "1.2 and later" (baseline versions).

**Errors:** RFC 9457 **Problem Details** (`ProblemDetail`) from `GlobalExceptionHandler`, with a stable
`type` URI, `title`, `status`, `detail`, plus extensions (`traceId`, `unavailableSkus`, field errors).
No stack traces, SQL or class names leak to clients (OWASP).

**REST design rules applied:** nouns for resources, plural collections; correct status codes (201/200/202/204,
400/401/403/404/409/422/429/503); idempotency for unsafe retries; `Location` headers; pagination
everywhere; ISO-8601 instants; money as `{amount: "12.50", currency: "EUR"}` (string decimal, never float);
OpenAPI at `/v3/api-docs` and Swagger UI at `/swagger-ui.html` (springdoc).

**HTTP interface client (Spring 7 HTTP Service Registry):**
```java
@HttpExchange(url = "/api/products", accept = "application/json")
public interface CatalogClient {
    @GetExchange("/{sku}/price") PriceResponse price(@PathVariable String sku);
    record PriceResponse(String sku, BigDecimal amount, String currency) {}
}

@ImportHttpServices(group = "catalog", types = CatalogClient.class)   // HttpClientsConfig
// application.yml: spring.http.serviceclient.catalog.base-url / connect-timeout / read-timeout
```
No implementation class: Spring generates a proxy backed by `RestClient`. This replaces OpenFeign.
The catalog endpoints are served by inventory-service (`CatalogController`, `/api/products/**`).
`CatalogPricingAdapter` adds caching, retries and a concurrency limit around it.

## 3. gRPC (`contracts/src/main/proto/inventory/v1/inventory.proto`)

```protobuf
service InventoryService {
  rpc CheckAvailability(CheckAvailabilityRequest) returns (CheckAvailabilityResponse);   // unary
  rpc ReserveStock(ReserveStockRequest) returns (ReserveStockResponse);                  // unary
  rpc StreamStockLevels(StreamStockLevelsRequest) returns (stream StockLevel);           // server streaming
}
```

* **Code generation:** `protobuf-maven-plugin` in `contracts` generates message classes and stubs at
  build time. Both services depend on `contracts`, so the contract is shared and compile-checked.
* **Server** (inventory-service `InventoryGrpcService`): `@GrpcService` extends the generated `ImplBase`;
  Spring Boot 4.1 gRPC auto-configuration starts the Netty server on port 9090. Errors map to
  `Status.INVALID_ARGUMENT` / `NOT_FOUND`.
* **Client** (order-service `GrpcInventoryAdapter`): `GrpcChannelFactory.createChannel(target)` with the target from `app.inventory.grpc-target` (`static://localhost:9090`),
  a blocking stub, **a deadline on every call** (`withDeadlineAfter(800ms)`), and a circuit breaker.
  Failure maps to `Availability.Unknown`, so ordering degrades instead of failing.
* **Protobuf evolution rules:** never change or reuse field numbers; mark removed fields `reserved`;
  new fields are optional to old clients; put the version in the package (`inventory.v1`).
* **Ops notes:** gRPC uses long-lived HTTP/2 connections, so an L4 load balancer pins a client to one
  pod. Use client-side load balancing (`dns:///` + `round_robin`), a service mesh, or an L7 load
  balancer. Health: the standard `grpc.health.v1` service.

## 4. GraphQL (`order-service/src/main/resources/graphql/schema.graphqls`)

```graphql
type Query {
  order(id: ID!): Order
  myOrders(limit: Int = 10): [Order!]!
  ordersByStatus(status: OrderStatus!, limit: Int = 20): [Order!]!
}
type Mutation { cancelOrder(id: ID!, reason: String!): Order! }
```

Controller annotations (`OrderGraphQlController`):

| Annotation | Role |
|---|---|
| `@QueryMapping` / `@MutationMapping` | Root fields |
| `@SchemaMapping(typeName = "Order", field = "total")` | Resolve one field per parent |
| `@BatchMapping(typeName = "Order", field = "lines")` | Resolve a field for **all** parents in **one** call: fixes GraphQL's N+1 problem (DataLoader) |
| `@Argument`, `@PreAuthorize` | Arguments, method security works as in REST |

**The N+1 problem:** `myOrders { lines { sku } }` for 20 orders would naively run 1 + 20 queries.
`@BatchMapping` collects the 20 order ids and calls `linesForOrders(ids)` (`= ANY(:ids)`) once, so 2
queries total. `OrderGraphQlControllerTest` (`@GraphQlTest`) checks it.

**Production hardening:** turn GraphiQL off (done in the `kubernetes` profile), limit query depth and
complexity (`MaxQueryDepthInstrumentation`), consider persisted queries, apply authorization per
field, and keep introspection off for public APIs.

## 5. How these combine in a request

```
browser ──REST──▶ api-gateway ──REST──▶ order-service ──gRPC (800 ms deadline)──▶ inventory-service
                                              │──REST (HTTP interface client)──▶ catalog prices
                                              └──Kafka events──▶ inventory-service (async saga)
```
